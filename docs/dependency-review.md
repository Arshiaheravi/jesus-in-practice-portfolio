CI now runs full development-dependency audits as well as its production-only audits, including the root Playwright/axe/Prettier lockfile, without suppressions.

Reviewed the official package metadata for [Next.js](https://registry.npmjs.org/next/16.4.1), [ESLint configuration](https://registry.npmjs.org/eslint-config-next/16.4.1), and [Zod](https://registry.npmjs.org/zod/4.6.6) before installation; also confirmed the installed [lint plugin's supported Zod range](https://registry.npmjs.org/eslint-plugin-react-hooks/7.1.1). The root/content/backend lockfiles only gain the shared override declaration.

## Remaining development-tool advisory

Both full audits report **braces 3.0.3**, [GHSA-vfj7-8cjw-p6xm / CVE-2026-93687](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), rated high. The advisory lists no patched version at the time of review. Its path is:

```text
eslint-config-next
  → @next/eslint-plugin-next
  → fast-glob
  → micromatch
  → braces 3.0.3
```

This is a development lint-tool path in the audited dependency graph; it is absent from both production dependency audits. It concerns failure when processing certain untrusted patterns. This review did not prove application-level reachability and does not declare the issue harmless. Keep lint/build jobs isolated and least-privileged, do not feed user-supplied glob patterns into these tools, and monitor the upstream fix. No advisory ignore, unsupported replacement, or fabricated patched version was added. A CI policy requiring a clean full audit would currently fail and needs an explicit project decision; do not report it as passing.

## Maintenance

Re-run both production and full audits when dependencies or published advisories change. Review the remaining braces finding and remove security overrides only after upstream resolutions are patched and verification passes. Keep Next.js and its ESLint configuration aligned. Prefer targeted supported updates over a broad upgrade, and repeat builds plus relevant frontend checks after dependency changes. Pin the release to the tested lockfiles and revision; no deployed service has been verified by this document.
